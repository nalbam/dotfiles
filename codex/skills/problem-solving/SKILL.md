# Problem Solving & Root Cause Analysis

AGENTS.md의 Before Changing Code·Problem Solving·Goal-Driven Execution을 구체화한다.

## Think Before Coding / 코딩 전 사고

- 요청·기존 코드에서 목표와 제약을 파악한다. 결과를 바꿀 모호함만 질문하고, 되돌릴 수 있는 세부 선택은 가정을 밝히고 진행한다.
- 더 단순한 해법이 있으면 근거와 함께 제안한다. 이미 합의한 결정을 반복해서 확인하지 않는다.
- 필요한 정보가 없으면 그 정보에 의존하는 작업만 보류하고 독립적으로 진행할 수 있는 조사를 계속한다.

## Goal-Driven Execution / 목표 기반 실행

작업을 검증 가능한 종료 조건으로 바꾼다. 다단계 작업은 단계별 검증 방법을 정하되, 자동화가 불가능하다는 이유만으로 사용자 확인을 강제하지 않는다.

| 작업 | 검증 기준 |
|------|-----------|
| 새 동작 | 정상·실패 입력에서 기대한 결과 |
| 버그 수정 | 원래 실패의 재현과 수정 후 회귀 확인 |
| 동작 보존 리팩토링 | 변경 전후 동일 테스트·동작 |
| 성능 개선 | baseline과 목표를 같은 조건에서 측정 |
| 문서 정리 | 실제 동작과의 일치·참조 유효성·중복 제거 |

## Investigation Steps / 조사 단계

1. 재현 조건·오류·환경과 최근 관련 변경을 확인한다.
2. 진입점부터 실패 지점까지 데이터·호출 흐름을 추적한다.
3. 가설을 최소 실험으로 확인한다. 첫 번째 그럴듯한 설명을 검증 없이 확정하지 않는다.
4. 확인한 원인을 수정한다. 임시 우회는 한계와 후속 해결을 밝힌다.
5. 관련 검사와 가능한 회귀 테스트로 확인하고 같은 원인이 다른 경로에도 있는지 살핀다.

재현이 어렵거나 환경에 막히면 확인한 사실·남은 가설·필요한 조건을 구분해 보고한다. 같은 실패에 근거 없는 재시도를 반복하지 않는다.
