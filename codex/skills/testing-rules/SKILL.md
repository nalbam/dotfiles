# Testing

AGENTS.md의 Testing을 구체화한다. 저장소의 기존 검사기와 변경 위험을 기준으로 검증 범위를 정한다.

## Goal-Driven Test Strategy / 목표 기반 테스트 전략

- 새 동작·버그 수정은 가능한 한 기대 동작이나 실패를 재현하는 테스트부터 작성한다.
- 동작 보존 리팩토링은 변경 전후 같은 검사를 실행한다. 성능 개선은 같은 조건의 baseline과 비교한다.
- 단순 문구·저위험 설정 변경은 문법·참조·diff 확인으로 충분할 수 있다. 구현을 그대로 복제하거나 존재 여부만 확인하는 테스트를 만들지 않는다.

## Test Quality / 테스트 품질

- 테스트 간 상태·실행 순서 의존을 제거하고 시간·랜덤·네트워크를 통제한다.
- 외부 경계를 mock할 때 실제 계약과 일치하는지 확인한다. 통합 흐름 전체를 mock으로 대체하지 않는다.
- 구현 세부 대신 관찰 가능한 동작을 검증하고, 실패 원인을 읽기 쉽게 드러낸다.

## Coverage / 커버리지

일괄 수치 목표를 두지 않는다. 변경한 중요 경로·경계 입력·오류 처리와 보안·데이터 손실 위험을 우선한다.

## Test Types / 테스트 유형

격리된 로직은 단위 테스트, 모듈·DB 경계는 통합 테스트, 핵심 사용자 흐름은 E2E, 공개 스키마는 계약 테스트로 검증한다. 모든 유형을 매번 실행하지 않는다.

## Failure Triage / 실패 분류

- 실패 출력·기대 동작·구현을 대조하고 새 회귀, 기존 실패, 환경 문제를 구분한다.
- 기존 실패라고 판단하려면 변경 전 상태나 독립된 최소 재현으로 근거를 확인한다.
- 구현이 계약을 어겼으면 구현을 고친다. 테스트 자체가 잘못됐다는 근거가 있을 때만 기대값을 바꾼다.
- 수정 후 관련 검사를 다시 실행한다. 통과 후 변경이나 새로운 근거가 없으면 같은 검사를 반복하지 않는다.
- 실패·미실행 검사를 숨기지 않고 이유와 남는 위험을 보고한다.
