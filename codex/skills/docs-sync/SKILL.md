# Documentation Sync

요청 범위의 코드와 문서를 대조해 부정확한 서술·누락·끊어진 참조를 고친다. 읽고 파악만 하는 요청은 `docs-read`의 범위다.

## 범위

- 기본 대상은 루트 안내 문서와 `docs/`다. 코드 주석·docstring·CHANGELOG는 요청에 포함된 경우에 다룬다.
- 생성 문서는 원본을 수정하고 재생성한다. 기존 문서 위치와 구조를 우선한다.
- 코드·문서 탐색은 `skills/code-audit/SKILL.md#exclude-patterns`를 참고한다.

## Workflow

1. 문서의 설치·실행 명령, CLI 플래그·환경변수, API·기본값, 아키텍처 설명을 대응 코드와 확인한다.
2. 부정확한 항목·삭제 후보·누락을 문서 위치와 코드 근거로 구분한다. 코드가 검색되지 않았다는 사실만으로 폐기된 기능이라고 단정하지 않는다.
3. 승인된 범위의 틀린 내용부터 고치고 중복은 참조로 합친다. 삭제 전 의도적으로 보존한 문서인지 확인한다.
4. 기존 문서에 넣을 수 없는 새 문서나 요청 밖 재배치는 근거를 제시하고 범위를 확인한다. 이미 승인된 정리·삭제를 다시 묻지 않는다.
5. 링크·앵커·예시를 확인하고 수정한 설명을 코드와 재대조한다. 상태 변경 명령은 권한과 격리 환경이 확인되지 않으면 실행 대신 코드로 검토한다.
6. 변경·검증 결과와 범위 밖 미해결 항목을 보고한다. 점검·보고만 요청한 경우에는 수정하지 않는다.

문서에는 현재 계약·제약을 기록한다. 자명한 코드와 자주 바뀌는 구현 목록을 복사하거나 시행착오를 누적하지 않는다.
