# Coding Style

CLAUDE.md의 Core Principles·Surgical Changes를 구체화한다. 프로젝트 관례를 우선한다.

## Surgical Changes / 외과적 변경

- 변경된 라인은 요청 해결에 필요해야 한다. 인접 코드의 스타일 변경·리팩토링·dead code 정리를 섞지 않는다.
- 기존 구조·이름·포맷·의존성을 유지하고, 새 추상화·주석·설정은 해결에 필요한 경우에만 추가한다.
- 본인 변경으로 발생한 unused import·변수는 정리한다. 기존의 무관한 문제는 별도로 보고한다.
- 동작 보존 리팩토링은 변경 전후 동일 동작을 검증한다.

## Immutability

공유 상태의 불필요한 변경을 피한다. 불변 패턴을 우선하되, 기존 API 계약·성능·소유권상 필요한 mutation까지 금지하지 않는다.

## File / Function Organization

줄 수로 파일·함수 분리를 강제하지 않는다. 책임·응집도·호출 흐름을 기준으로 판단하고 기존 유틸리티를 재사용한다.

## Error Handling

- 처리하거나 맥락을 더할 수 있는 오류만 잡는다. 구체적인 실패를 구별하고 원인을 보존한다.
- 실패를 성공 값으로 숨기지 않는다. 복구 불가능한 오류는 호출자가 처리할 수 있게 전달한다.
- 로그에는 진단에 필요한 맥락만 남기고 민감 정보는 제외한다.

## Input Validation

사용자 입력·외부 API 등 신뢰 경계에서 검증한다. 내부 호출은 확인된 타입·불변식을 활용하며 같은 검증을 기계적으로 반복하지 않는다.

## Documentation

- 주석은 코드만으로 알기 어려운 이유·계약·제약을 설명한다. 잘못된 주석은 현재 동작에 맞게 고치거나 불필요하면 삭제한다.
- 변경한 사용법·API 계약과 관련 문서를 함께 갱신한다. 기존 문서와 프로젝트의 배치 관례를 우선한다.
- 문서·주석은 현재 동작을 기록한다. 시행착오·추측을 누적하지 않으며, 변경 이력은 git·PR·CHANGELOG에 둔다.
- 한국어 문체는 `rules/language.md`를 따른다.
