# Git Workflow

- 요청한 목표에 필요한 브랜치 생성·수정·검증·commit·push·PR 생성·충돌 해결은 별도 승인 없이 수행한다. push 전에 원격 목적지와 반영할 커밋을 확인한다.
- **merge 권한은 대상(base) 저장소의 소유자로 정한다.** PR·MR merge, 기본 브랜치 push, 자동 merge 예약에 적용한다.
  - 내 소유 저장소: 소유자 namespace가 인증된 내 계정(`gh api user`의 login) 또는 내 소유 조직 `opspresso`다. 소유자는 PR·MR의 base 저장소를 지정해 `gh repo view OWNER/REPO --json owner`로 확인한다. PR·MR이 merge 가능 상태이고 필수 검사·CI가 통과하면 별도 승인 없이 merge한다. 기본 브랜치 직접 push도 같은 검사 조건과 브랜치 보호를 충족할 때만 한다.
  - 내 소유가 아닌 저장소(다른 조직·다른 사용자·fork 원본): 해당 PR·MR merge·자동 merge 예약 또는 기본 브랜치 push에 대한 사용자의 명시적 허락이 있을 때만 실행한다. 허락은 지정한 PR·MR·push에만 적용한다. 허락이 없으면 merge 준비 상태를 보고하고 멈춘다.
  - 소유자를 확인할 수 없으면 내 소유가 아닌 저장소로 처리한다.
- **문제가 없음을 검증한 릴리즈·배포는 별도 사용자 승인 없이 자율 수행한다.** 읽기 전용 요청이나 사용자가 명시한 중단 지점을 넘지 않는다.
- merge·기본 브랜치 push·릴리즈·배포 전에 실행할 커밋의 필수 검사·CI·리뷰가 통과했고, 미해결 차단 문제·충돌이 없으며, 대상과 영향이 명확한지 확인한다. 리뷰는 브랜치 보호가 요구하는 승인을 뜻한다. CodeRabbit 같은 자동 리뷰는 참고용이다. 지적 사항은 반영하고, 사용량 한도·오류로 리뷰하지 못하면 전체 diff를 직접 검토한 것으로 대신한다. 대기·실패·미실행 검사를 통과로 간주하지 않으며 브랜치 보호·필수 리뷰·환경 승인·도구의 강제 제한을 우회하지 않는다.
- 실패나 확인되지 않은 위험이 있으면 해당 단계를 보류하고 요청 범위에서 원인을 해결·재검증한다. 사용자 판단이나 권한이 반드시 필요할 때만 대상·문제·필요한 조치를 설명하고 질문한다.
- 릴리즈·배포 후 해당 버전의 워크플로·산출물·대상 환경의 반영 상태와 정상 동작을 확인한다. 태그 생성이나 배포 시작만으로 완료라고 하지 않는다.
- 릴리즈 완료를 확인하면 해당 작업의 로컬·원격 브랜치를 정리한다. 삭제 전 merge 반영과 미반영 커밋·미커밋 변경·다른 worktree 사용 여부를 확인하고, 기본 브랜치·다른 작업 브랜치·사용자 변경은 보존한다.
- 기존 작업 트리·index의 무관한 변경을 되돌리거나 본인 커밋에 섞지 않는다.
- 변경 폐기·이력 정리·브랜치 삭제는 요청 범위와 기존 작업 보존을 확인한 뒤 필요한 경우에만 수행한다. 본인 작업 브랜치의 이력을 다시 push해야 하면 원격 변경을 확인하고 `--force-with-lease`를 사용한다.
- 커밋 메시지·PR 본문에 `Co-Authored-By`, `Generated with`, 도구 귀속 푸터·배지를 넣지 않는다.
