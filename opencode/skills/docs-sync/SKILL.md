# Documentation Sync

요청 범위의 코드와 문서를 대조해 부정확한 서술·누락·끊어진 참조를 고친다. ISO 24495-1의 네 관점으로 찾기·이해·사용을 돕고, ASD-STE100의 원칙을 참고해 문장을 짧고 명확하며 모호하지 않게 쓴다. 읽고 파악만 하는 요청은 `docs-read`의 범위다.

## 범위

- 기본 대상은 루트 안내 문서와 `docs/`다. 코드 주석·docstring·CHANGELOG는 요청에 포함된 경우에 다룬다.
- 전체 파일 검토 요청이면 추적 파일과 관련 미추적 파일을 목록화하고 코드·설정·테스트·주석·문서를 모두 확인한다. 생성물은 원본과 변환 결과를 대조하고 확인한 범위와 제외 항목을 보고한다.
- 생성 문서는 원본을 수정하고 재생성한다. 기존 문서 위치와 구조를 우선한다.
- 의존성·캐시·빌드 출력은 해당 설명 검증에 필요한 경우에만 읽는다.

## Workflow

1. 요청과 기존 문맥에서 독자·목적·완료 조건을 파악하고 검토할 파일을 정한다.
2. 문서의 설치·실행 명령, CLI 플래그·환경변수, API·기본값, 아키텍처 설명을 대응 코드와 확인한다.
3. 부정확한 항목·삭제 후보·누락을 문서 위치와 코드 근거로 구분한다. 코드가 검색되지 않았다는 사실만으로 폐기된 기능이라고 단정하지 않는다.
4. 승인된 범위의 틀린 내용부터 고치고 중복은 참조로 합친다. 삭제 전 의도적으로 보존한 문서인지 확인한다.
5. 기존 문서에 넣을 수 없는 새 문서나 요청 밖 재배치는 근거를 제시하고 범위를 확인한다. 이미 승인된 정리·삭제를 다시 묻지 않는다.
6. 링크·앵커·예시와 작성 품질을 확인하고 수정한 설명을 코드와 재대조한다. 상태 변경 명령은 권한과 격리 환경이 확인되지 않으면 실행 대신 코드로 검토한다.
7. 변경·검증 결과와 범위 밖 미해결 항목을 보고한다. 점검·보고만 요청한 경우에는 수정하지 않는다.

문서에는 현재 계약·제약을 기록한다. 자명한 코드와 자주 바뀌는 구현 목록을 복사하거나 시행착오를 누적하지 않는다.

## 작성 품질

| 관점 | 확인할 내용 |
|------|-------------|
| 필요한 정보 | 대상 독자의 작업·판단에 필요한 내용과 제약이 있고 불필요한 설명이 적은가 |
| 찾기 쉬움 | 제목·순서·링크로 필요한 내용을 찾을 수 있고, 공통 정보와 조건별 정보가 구분되는가 |
| 이해하기 쉬움 | 문장이 짧고 직접적이며, 용어·행위 주체·대상·조건이 명확하고 낯선 전문 용어가 설명되는가 |
| 사용하기 쉬움 | 실행 위치·사전 조건·행동·예상 결과와 필요한 실패 대처가 있어 다음 행동을 결정할 수 있는가 |

간결하게 줄이면서 식별자·명령어·필수 조건·예외·인과관계·의무 수준이 바뀌거나 빠지지 않았는지 원문·코드와 대조한다. 근거가 없는 동작이나 결과를 추가하지 않는다.

에이전트 자체 검토와 실제 독자의 사용성 검증을 구분한다. 실행하지 않은 절차나 사용자 검증을 완료했다고 표현하지 않으며, 이 점검만으로 표준 전체 준수를 주장하지 않는다.
